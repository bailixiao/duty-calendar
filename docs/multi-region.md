### 2.2 畫面
- 標題寫自己的區名，例如「教真區行事曆」；開場動畫也一樣。
- 加到主畫面時，圖示下面的名字是「教真區行事曆」，點開直接進教真區。
- 畫面、功能和教全區完全一樣。各區可以關掉用不到的功能，例如沒有場地可借，就把「借場地」「修繕回報」關掉。
- 家人們看不到別的區，也不會不小心報到別區的勤務。

### 2.3 同一支手機看兩個區
- 有些人可能兩個區都會看（例如家人在不同區）。
- 每個區記在手機裡的東西分開記，例如「查我的報名」的名字、上次選的檢視、字體大小、後台登入。教真區登入後台，不會把教全區的登出。
- **手機提醒**：開了兩個區的提醒，兩個區的提醒都會收到，通知標題寫區名分得出來。

## 3. 管理者

### 3.1 每區各自管理
- 每區有自己的**總管理者**，帳號、角色和現在一樣（總管理者、勤務、道務、教育、唯讀、場管），只能管自己的區。
- 各區自己的成員名單、分組、勤務、報名、統計、操作紀錄、常見問題、推播、場地借用，互相看不到。

### 3.2 開一個新區的流程
1. 使用者告訴 Claude 要開哪一區。
2. Claude 用工具建好這一區，產生一個「**開通連結**」，只能用一次、7 天內有效。
3. 使用者把開通連結交給那一區的總管理者，由他自己設定總管理者密碼。**Claude 不碰真的密碼。**
4. 總管理者登入後，在後台新的「⚙️ 區設定」填這一區的資料（見 3.3），就可以開始新增勤務、成員。

### 3.3 後台「⚙️ 區設定」（只有總管理者）
現在這些是寫在程式裡的（`js/site.js`、`Config.gs` 的 `SITE`），改成每區在後台自己填：
- 區名（例：教真區）
- 場地名稱（例：區中心）
- 新增勤務時的地點選項
- 三個類別的顯示名字（總務・勤務／道務／教育）
- 教育統計看哪幾個班
- 缺人通知、邀請通知的標題
- 「國外」的選項
- 功能開關：借場地、修繕回報、常見問題、手機提醒
- 管理者聯絡人（畫面上「請聯絡管理者」那句話）

### 3.4 新區一開始有什麼
- **勤務**：空的，由各區自己新增（教全區的初一十五、12人小組等不會帶過去）。
- **常見問題**：用共用的預設題目。題目裡寫到「區中心」「教全區」的地方，自動換成這一區的名字；各區總管理者也可以自己改。
- **勤務頁的重點圖片**（12人小組值勤事項等）：各區都有（2026/11/19 使用者決定，各區也去彌勒山母殿輪值）；勤務名稱有「12人小組」就會出現。

### 3.5 資料備份（新的區沒有 Google 試算表）
- 資料存在 Cloudflare，本身不會掉；但還是要有備份。
- 後台「統計」旁加「⬇ **下載全部資料**」（總管理者）：一個 Excel 檔，成員、分組、勤務、報名、場地借用各一個工作表，不含帳號密碼。
- 系統每週自動備份一份在 Cloudflare 裡，保留最近 8 週，出事時可以請 Claude 還原。
- 教全區的 Google 試算表同步**照舊**（已經在用，不動它）。

## 4. 技術做法（給 Claude）

### 4.1 後端（Cloudflare Worker）
- 現在：所有請求都進同一個 Durable Object，名稱 `main`。
- 改成：**一區一個 Durable Object**，名稱就是區代號（`zhen`、`shan`⋯）。**教全區繼續用 `main`**，資料不用搬。
  - 每個 Durable Object 有自己的 SQLite，資料、快取、登入、指令碼屬性天生就分開。
- 前端呼叫 API 時多帶 `region=zhen`（GET 放網址參數，POST 放在 body）。沒帶的就是教全區，所以舊版網頁也照常運作。
- Worker 收到不認得的區代號就回錯誤，不會自動建新區。
- 區的清單：存在 `main` 的指令碼屬性 `REGIONS`。新增區用 `tools/new-region.js`（要用 Worker 的秘密金鑰 `REGION_ADMIN_KEY`，存在 Cloudflare secret，不放 repo）。
- **排程**（每天兩次提醒、每 5 分鐘排定推播）：輪流叫每一區的 Durable Object。
- **區設定**：存在各區的指令碼屬性 `SITE_JSON`。`Config.gs` 的 `SITE` 改成「預設值＋各區的設定蓋上去」；教全區沒有填的就用現在的值，所以完全不變。
- **推播金鑰**（VAPID）：13 區共用同一組，存在 Worker secret。因為同一個網站在手機上只能有一組推播金鑰，用不同組的話，開第二個區的提醒會把第一個區的弄壞。推播網址各區自己記。手機收到通知後來拿內容時，帶上是哪一區。
- 防止亂報名、AI 讀照片、檔案上傳：照舊，各區分開算。

### 4.2 前端（Cloudflare Pages，2026/11/19 前是 GitHub Pages）
- 13 區用同一份 `index.html`、js、css。
- `tools/build-regions.js` 幫每一區產生一個資料夾（`zhen/`、`shan/`⋯），裡面只有：
  - 很小的 `index.html`：設定區代號，再載入上一層的共用檔案。
  - 這一區的 `manifest.webmanifest`：名稱、`start_url` 是這一區。
- 進網站時：
  1. 從網址知道是哪一區。
  2. 跟伺服器拿這一區的設定（區名、場地、功能開關⋯）。
  3. 套用設定，存在手機裡，下次打開立刻出現。
- 手機裡記的東西（`duty-calendar:` 開頭的 32 種）改成每區分開：教全區用原本的名字（不用重設），其他區前面加區代號。
- Service Worker 共用一個：13 區的網頁檔案只存一份，不會多佔手機空間。

### 4.3 Google 試算表（只有教全區）
- Apps Script 同步照舊，只同步教全區（`main`）。
- 其他區沒有 Google 端，原本 Google 端做的事要搬到 Cloudflare：
  - 「試算表同步停了」通知：沒有試算表就不檢查。
  - 統計分頁：後台的統計畫面本來就在 Cloudflare 算，不受影響。
  - 每週備份：改成 3.5 的 Cloudflare 自動備份。

### 4.4 測試
- 新增測試：兩個區的資料不會互相看到（報名、成員、登入、推播、檔案）；沒帶區代號的請求還是教全區；不認得的區代號會被擋。
- 測試版（mock）可以同時開好幾個區：`http://localhost:5175/zhen/`。

## 6. 使用者的決定（2026-11-19）

1. **網址代號**：用 2.1 那張表的拼音。
2. **試用區**：教捨區（`she`）。
3. **費用**：用免費方案就夠（見 6.1）。
4. **截圖**：其他區先共用教全區的截圖。
5. **跨區活動**：這一版不做，各區完全分開。

### 6.1 Cloudflare 免費額度
- 免費額度是**整個 Cloudflare 帳號**一起算：每天 10 萬次請求，13 區加起來。
- 分成 13 個 Cloudflare 帳號就各自有免費額度，但要管 13 個帳號、每次改程式部署 13 次，又回到「複製 13 份」的麻煩，不建議。
- 免費方案超過額度**不會自動扣錢**，而是那天剩下的時間網站讀不到資料，到隔天台灣早上 8 點才恢復。
- **實際用量（2026-11-19 在 Cloudflare 後台查）**：教全區近 30 天共約 5,100 次，平均一天不到 200 次，最多的一天約 1,000 次（今天 744 次）。整個帳號的 Durable Object 儲存空間 8.7 MB（免費 5 GB）。
- 估算：13 區就算每區都跟教全區最忙的那天一樣（1,000 次），一天約 1.3 萬次，加上排程約 3,800 次，**不到免費額度的 2 成**。
- **決定：用免費方案**。另外加「用量提醒」，當天用到 8 成就通知使用者；真的常常接近上限，再改付費（每月 5 美元）。
