# 教全區行事曆系統 — 開發規格書

> 本文件是給開發者（含 Claude Code）的完整需求說明。所有開發都以本文件為準，需求有變動時先更新本文件。
> 本儲存庫是**公開的**（GitHub Pages 免費方案只能用公開儲存庫），因此**任何人名、電話、成員名單都不可以出現在程式碼或本儲存庫中**，一律放在 Google Sheet。

---

## 1. 一句話目標

教全區行事曆（2026/10/4 起由「教全區勤務行事曆」改名，因為道務、教育的活動也放上來）：總務組派下來的全年勤務，以及道務、教育的法會、課程、活動，都放在一個行事曆上，區裡任何人都能看、能幫自己或長輩報名、取消、改期，額滿自動擋；管理者（總務）從電腦或手機管理，並自動產生每月勤務統計表。

## 2. 使用者與權限

| 角色 | 說明 | 權限 |
|---|---|---|
| 一般使用者 | 教全區道親、壇主辦事，含長輩；常由年輕人代報 | 看行事曆、報名（可一次幫多人報）、取消、改期 |
| 管理者 | 總務（只有一人） | 一般使用者全部功能 + 管理後台 |

- **不做登入**。報名只填名字，不需電話或密碼。
- 組長**沒有**特別權限，跟一般使用者一樣。
- 管理後台用一組「管理密碼」保護，密碼存在 Apps Script 的 Script Properties，不寫進程式碼。
- **後台帳號與權限（2026/10/4）**：登入改成「帳號＋密碼」。角色：**總管理者**（原本的管理密碼，帳號欄留空或填「總管理者」；全部功能，含「帳號」分頁管理其他帳號）、**勤務／道務／教育**（只能新增、修改、刪除自己類別的勤務，及其報名的取消、改期、出席、補登、還原；成員、分組只能看；**操作紀錄只有總管理者看得到**；「名單」總管理者看全部、勤務／道務／教育帳號只看自己類別）、**唯讀**（都不能改；只看近期勤務（含名單）、成員、分組、統計，看不到勤務管理、操作紀錄、名單）。登入畫面的帳號是下拉選單（總管理者＋啟用中的帳號，依角色排序：勤務、道務、教育、唯讀），記住這台裝置上次選的。道務、教育的活動自由參加、鼓勵為主，**不算缺人**（卡片顯示「已報 N 人」，不出現在缺人提示、缺人通知、推播的「還需要人手」；道務、教育帳號的近期活動頁不顯示缺人框）。**道務、教育的表單較簡單**：性質只有道務「法會／課程」、教育「課程／活動」（伺服器依類別檢查），沒有負責組、沒有了愿項目，只有「名額」（不限名額／限定人數；存成一個「參加」項目，最多＝限定人數）；報名頁不用選項目，直接填名字；後台表單用詞跟著該筆類別叫「活動」。道務、教育、唯讀帳號的畫面用詞改為「活動」（近期活動、活動管理、新增活動、活動場次）。每個勤務有「類別」（勤務／道務／教育，舊資料視為勤務）；類別帳號的勤務列表、近期、明日名單、統計只看到自己類別，新增時類別固定。權限由伺服器檢查（Accounts.gs 的 adminAuthorize_、adminScope_）。帳號存在「帳號」分頁，密碼只存加鹽雜湊，此分頁不同步到 Google 試算表。每個帳號各自一台裝置登入；改密碼、停用、改角色後該帳號的登入立即失效。操作紀錄記下帳號名稱。家人們的行事曆：有道務或教育項目時上方出現「全部／總務・勤務／道務／教育／借場地」篩選（「借場地」只看區中心場地借用）（記住選擇），每張卡片都有類別小標籤（勤務類寫「總務・勤務」赭紅、道務紫、教育藍綠；舊資料沒有類別的算勤務），報名頁標題上方也有；手機提醒不分類別。
- **一次只能一台裝置登入管理後台**：在新裝置登入後，其他裝置自動登出（停在管理後台時約 30 秒內、或切回該分頁／視窗時就會跳回登入畫面，顯示「管理後台已在其他裝置登入，這台已自動登出」）。
- 畫面上「請聯絡管理者」會接上管理者聯絡人（Script Properties 的 `ADMIN_CONTACT`，例如「○○○ 後學」）。人名一律不寫進程式碼。

## 3. 技術架構

| 層 | 技術 | 說明 |
|---|---|---|
| 前端 | 單一 HTML/CSS/JS，放 GitHub Pages | 手機優先的響應式網頁（Web App，不上架 App Store） |
| 後端 API | **Cloudflare Workers ＋ Durable Object（2026/10/4 正式切換）**；原 Google Apps Script Web App 保留為備援 | 提供 JSON API 給前端呼叫（API 格式不變）。Apps Script 每次回應固定 1.5～2 秒、寫入常 3～5 秒；Cloudflare 約 0.1～0.3 秒 |
| 資料 | 正本：Durable Object 內建的 SQLite；副本：Google Sheet（每 10 分鐘自動同步） | 管理者在 Sheet 看資料、下載 Excel、每週備份照常；**改資料一律用管理後台**（直接改 Sheet 不會回寫）|
| 行事曆元件 | FullCalendar（CDN） | 年／月／週檢視（另有自製的「近期」列表） |
| 農曆換算 | lunar-javascript（CDN） | 顯示農曆日期、產生初一十五勤務（含閏月） |

注意事項：
- 報名寫入時用 `LockService` 鎖定，避免兩人同時搶最後一個名額造成超收。
- 時區一律為台北時間（`appsscript.json` 的 `timeZone` 設為 `Asia/Taipei`），所有「當天」「已過去」的判斷都以台北時間為準。
- 日期在 Sheet 中一律存成 `yyyy-MM-dd` 純文字、時間存成 `HH:mm` 純文字，避免 Sheet 自動轉換格式。
- API 絕不回傳電話等個資。
- Apps Script 程式碼也存一份在本儲存庫的 `apps-script/` 資料夾做版本管理，由 Claude 用 clasp 上傳部署（2026/10/3 起，不再手動貼檔案）。
- **Cloudflare 版**（`worker/`）：建置時把 `apps-script/*.gs` 原封不動包進 Worker，換掉讀寫試算表、快取、鎖等底層（`worker/src/runtime.js`），所以報名規則、名額檢查、統計等邏輯與 Apps Script 版完全相同；需要對外連線的（推播、AI 讀照片）改寫成非同步版。所有請求都進同一個 Durable Object（依序處理，等同鎖定），資料存在它的 SQLite。Google Sheet 由 Apps Script 每 10 分鐘向 Worker 拿資料寫入（含統計分頁、每週備份）。
- 前端只放 Apps Script API 網址，不放任何資料。

## 4. 勤務的兩種模式

| 模式 | 適用 | 系統行為 |
|---|---|---|
| 報名型 | 打掃、佛堂分組勤務、12人小組、割草、志工輪值、烹飪團輪值、法會支援等 | 顯示負責組與其組長或召集人（12人小組不顯示；電話只在管理後台），開放全區任何人報名，有了愿項目和名額 |
| 公告型 | 初一十五拜香輪值（拜香開課） | 只顯示「本次輪值第幾組」與組長、佐理、組員、服裝與工作項目，**不需報名** |

「分組」只是預設名單，不代表一定出席。報名型勤務即使有負責組，仍然全區開放報名。

分組類型有三種，各有用途：
- **勤務了愿組**（原稱佛堂組）：佛堂分組勤務輪值（如彌勒山志工輪值），仍要報名。
- **打掃組**：初一十五宏宗、區中心、彌勒山打掃，仍要報名。
- **拜香輪值組**：初一十五拜香開課輪值，公告型，不需報名。

## 5. 勤務的日期型態（第一版）

| 型態 | 例子 |
|---|---|
| 單日 | 宏宗打蠟 116/1/31 8:00 |
| 連續多天 | 12人小組 11/8–11/15（週日到週日共 8 天，週日 14:00 交接） |
| 農曆規則產生 | 每月初一、十五（含閏月），一次產生一整年的單日勤務 |

- 時段可跨日，例如除夕值夜 21:00 至隔天 08:00。跨日的單日勤務：開始日＝結束日，結束時間早於或等於開始時間即代表到隔天；報名日期記在開始那天。
- 連續多天的勤務，報名以「每一天」為單位，名額每天分開計算。
- 打掃勤務固定掛在初一、十五當天；組員實際哪天去由他們自己協調，系統不管。
- 同一輪 12人小組可能與他區分段接（例如 15 號晚上交接），勤務需能只涵蓋其中幾天。

## 6. 了愿項目與名額

> 原稱「崗位」，畫面、試算表一律改稱「**了愿項目**」（程式內部變數仍用 position）。

- 一個勤務底下可有多個了愿項目，每個了愿項目有「最少」「最多」人數。「最多」留空代表不限；**「最少」留空預設 2 人**（「最多」小於 2 時以最多為準），要不同人數就在試算表填「最少」。
- 例：12人小組 = 烹飪 4、清潔 最少 2 最多 4、早上維安 2、晚上維安 2（每天 10–12 人）。
- 例：人才班 = 交通 2、茶水 2、勤務 4。
- 例：志工輪值 = 志工 2。
- 到「最多」→ 擋住不能再報，顯示「額滿」。
- 未達「最少」→ 行事曆標示「缺 N 人」。
- 不到最少人數（含預設 2 人）一律標示紅色「缺 N 人」，避免誤以為人數已足；達到後，不限人數的勤務（打掃、割草）顯示「已報 N 人」，其他顯示「人數足」。

## 7. 報名規則

1. 報名只填名字；輸入時從成員名單自動提示（負責組的組員排最前面），可一次加多人。
   - **每個人可以各自選了愿項目**：上方選的項目是大家共用的（名字卡只顯示「同上面」）；某人要報不同項目，按他名字卡的「這個人改報別的」再自己選，可按「改回跟上面一樣」（一般勤務每人一項）。**可兼任的勤務**（有多個項目）上方不顯示了愿項目區塊，每加入一個名字，就在他的名字卡勾他要報的項目（可多項；已額滿的項目變灰、標「額滿」不能勾），避免上下兩處都能選而混亂。按一次「確認報名」整批送出（任一項不能報就都不寫入）。
   - 為保護名單，API 不提供整份成員名單：至少輸入一個字才回傳，只回名字含有該字的成員姓名、身分與組別，最多 10 筆。
   - **每個名字都必須選「道親」「壇辦」或「未求道」**（未求道：還沒求道的人；統計時算進道親）（不預設，沒選不能送出；陪同者也要選），統計道親佔比用。成員名單上已登記身分的人，報名時自動帶入且**不能修改**（伺服器存檔時也以成員名單為準）；要改身分請到管理後台的成員名單。名單上沒有身分的人才由報名者選。
2. 名字不在成員名單上也允許報名（臨時新道親），管理者事後可補進名單。
3. **同一人同一天在同一個勤務內只能報一個了愿項目**，重複則擋下並提示；不同勤務同一天可以各報一個。
   - 名字比對時先去掉前後空白（含全形空白）。
   - **名字相近視為同一人**：三個字以上的名字先去掉第一個字（姓），剩下的部分只要有連續兩個字相同就視為同一人（例：「小明」與「王小明」）；一個字的名字只比對完全相同。同一批填寫多人時也適用。
   - 一次報多人時，只要其中一人被擋（額滿或重複），整批都不寫入，並列出被擋的人與原因。
4. **勤務當天（含）之後不能自己報名**（與第 6 條取消、改期一致；當天需要報名請聯絡管理者）。改期的新日期也不能是當天。
5. 取消、改期任何人都能做，但要跳出確認視窗（顯示：姓名、日期、勤務、了愿項目）。
   - **改期範圍**：可改到「同名勤務」的其他日期（例如彌勒山志工輪值 10/13 → 10/24；多天勤務如 12人小組可改到其他天），改期時也可換了愿項目。
   - 改期的新日期與一般報名一樣檢查名額、同日重複、是否已過；不符合就整筆不動（原報名保留）。
   - 改期 = 原報名改為「已取消」＋建立一筆新報名（同一次鎖定內完成）。
6. **勤務當天（含）之後不能自己取消或改期**，畫面提示「請聯絡管理者」。管理者可以取消、改期任何日期的報名。
7. 每次報名、取消、改期都寫入操作紀錄，管理者可一鍵還原：
   - 報名 → 還原＝取消該筆；取消 → 還原＝恢復該筆；改期 → 還原＝取消新的一筆、恢復原本那筆。
   - 還原時若會超過名額或造成同日重複，**照樣還原但顯示警告**（管理者有最終決定權）。
   - 已還原的紀錄標示還原時間，不能重複還原；還原本身也寫入操作紀錄。
8. 道親一律是「了愿」；**只有壇辦**可再選「了愿」或「陪同」（預設了愿，用按鈕選，不用勾選框）：陪同者記錄在統計表備註欄，**不計入人數與道親佔比，不佔了愿項目名額，也不受第 3 條同日重複檢查限制**（用於壇主辦事陪同道親的情況）。

## 8. 畫面

### 一般使用者（手機優先）
0. **開場與讀取速度**：打開網站時顯示開場動畫（logo 由小變大再放大淡出 → 一個字一個字浮現「教全區行事曆」→ 名稱滑到左上角成為頁首標題 → 行事曆展開；各段重疊接續不停頓，約 3.5 秒；系統設定「減少動態效果」時不播），同時用 getBundle 一次拿回今年行事曆＋今天起 30 天每個勤務的詳情與名單（Apps Script 每次回應固定約 2 秒，一次打包比點進每個勤務各等一次快）。勤務詳情記在這台瀏覽器：點進勤務立刻連名單一起顯示，30 秒內拿到的不再問伺服器，較舊的在背景更新（不清掉正在填的報名表）；手指碰到勤務連結就先讀。網頁先跟 Google 建好連線（preconnect）。讀取請求超過約 3.5 秒沒回來就同時再送一個（前一個不取消，先回來的用），最多 4 個；伺服器明確回錯誤不重問；寫入不重送。伺服器把 getEvents／getBundle／getDuty 算好的結果存在 CacheService（名稱含相關分頁版本號與日期，有寫入就自然換新，5 分鐘到期），keepWarm 每 5 分鐘先算好今年的打包資料，並在試算表被直接修改（不觸發 onEdit）時讓快取失效。網頁檔案由 Service Worker（sw.js）存在手機裡：網頁本身先向網路拿最新（3 秒拿不到用手機裡的），帶版本號的 js／css 與固定版本外部函式庫直接用手機裡的（新版本出現時刪掉舊版），圖示、圖片、字型先用手機裡的同時背景更新；資料 API 一律不經過。第二次打開幾乎立刻出現，沒網路也能看上次的資料。管理後台：進後台就在背景同時抓近期勤務、勤務管理、成員、分組、操作紀錄、明日名單、統計，切換分頁立刻顯示（20 秒內抓到的不再問伺服器，較舊的先顯示再更新）；寫入後全部重新抓。管理資料只記在記憶體，不存進手機。
1. **行事曆首頁**：年／月／週／近期切換（記住上次選的，第一次預設月）；格子顯示國曆＋農曆日期與勤務色點；點日期在下方列出當天勤務卡片（名稱、地點、時段、人數、缺人／額滿標示）。
2. **週檢視**：一週七天直向列出，每天的勤務與人數狀態。
   - **手機提醒（推播，簡單版）**：行事曆上方「🔔 手機提醒」可開啟／關閉／傳測試通知；第一次打開網站（開場動畫後）出現詢問卡片「要開啟勤務提醒嗎？」，按「以後再說」兩週後再問（已開啟、已封鎖、不支援或管理者尚未設定時不顯示）。通知一定要本人按允許，網站不能自動開啟。開啟的手機每天晚上 8 點收到明天、早上 7 點收到今天的勤務／活動（沒有勤務不送），內容列出前 4 項、時間、缺幾人，點通知打開該勤務（只有一項時）或「近期」。所有開啟的手機收到相同內容，不需名字。iPhone 須先「加到主畫面」並從主畫面圖示打開才能開啟，會顯示圖文步驟。在 LINE 內建瀏覽器開啟（收不到通知）時，卡片與視窗改為提示「用瀏覽器開啟」，按鈕網址加上 LINE 官方參數 openExternalBrowser=1 跳到 Chrome／Safari；「複製缺人通知」的連結也都加上這個參數。技術：推播不帶內容，手機收到後 sw.js 以推播網址的 SHA-256 代號向 pushSummary 取內容；Apps Script（Push.gs）以自行實作的 P-256 ES256 簽 VAPID JWT（測試以 Node crypto 驗證），每個推播服務簽一次，fetchAll 並行送出，404／410 自動停用。試算表「推播」分頁只記推播網址（無個資）。管理者第一次在編輯器執行 setupPush（建分頁、產生金鑰存 Script Properties 的 VAPID_PRIVATE／VAPID_PUBLIC、建每天兩次排程）。
   - **我的報名**（行事曆上方「查我的報名（取消／改期）」按鈕，#/mine）：輸入名字，列出這個人今天起還有效的報名（日期、勤務、了愿項目、時間地點），可直接「取消」（同一般取消：確認視窗、當天含之後不能自己取消），也可以勾選多筆（上方「全選／都不選」）後「取消勾選的報名」一次取消；「改期」直接在這頁打開改期視窗（活動不顯示改期）。**取消與改期只能在這裡做**（勤務頁名單不再有按鈕，避免誤按到別人的）。打字時跟報名一樣從成員名單提示名字（打一個字就提示），點一下就查。只比對完全同名（去掉空白），名字用 POST 送、不放網址；上次查的名字記在這台瀏覽器。
   - **加到手機行事曆**：報名成功訊息（每個日期一個按鈕，最多 7 個）與我的報名每一筆都有「加到手機行事曆」按鈕。iPhone／iPad 下載 .ics（系統跳出加入行事曆，前一天晚上 8 點提醒）；其他裝置開 Google 日曆新增畫面。單日有時間的勤務照時間（無結束時間算 2 小時、結束早於開始算隔天），多天或沒寫時間的算整天。內容只有勤務名稱、時間、地點、報名頁連結，不含名字。
   - **近期檢視**：今天起一個月有勤務的日子依序列出（不能翻頁），最上面紅框提醒「近一個月有 N 天缺人」與日期（超過 8 天只列前 8 天＋「⋯等 N 天」），點勤務直接進報名頁；內容與管理後台的近期勤務相同（都是公開資料）。
   - **缺人通知**：近期檢視與管理後台近期勤務的缺人紅框裡有「複製缺人通知」「傳到 LINE」兩個按鈕，產生依日期排列的缺人勤務清單（勤務名稱、缺幾人、時間、地點、各自的報名連結），貼到 LINE 群組。只含公開資料，不含名字、電話。
3. **勤務詳情與報名**：勤務說明、地點、時段、服裝規定、負責組 → 選了愿項目（額滿反灰）→ 填名字（可多人）→ 確認報名。
4. **報名名單**：依了愿項目列出已報名者（只顯示名字；下方提示「要取消或改期，請到『查我的報名』」附按鈕）。行事曆格子上**只顯示人數，點進來才看得到名字**。
5. **重點圖片**：勤務頁可在說明下方顯示說明圖片（例如 12人小組的值勤事項、拜香與清潔 SOP、餐點份量參考），點圖片放大，也可開新頁看原圖。圖片放在 `img/duty/`、對應設定在 `js/duty-images.js`；圖片與網站一樣公開，不可放有人名、電話、人臉的照片。
6. **公告型勤務頁**：顯示本次輪值組、組長、佐理、組員、服裝與工作項目，沒有報名按鈕。

設計風格：整潔安靜，米白底、深墨色字、赭紅色重點色；標題用明體、內文用黑體；按鈕夠大方便長輩點（至少 44px）。

### 管理者後台（電腦與手機皆可）
1. **近期勤務列表**：今天起一個月，日期、勤務、人數、狀態（缺人／額滿／人數足），頂部提示近期缺人天數。每筆有「📋 複製通知」：【名稱】、日期（民國）、時段、地點、需要人數（勤務：還缺 N 位（共需 M 位）／已額滿；道務、教育：名額還有 N 位或「歡迎參加」）、「歡迎家人們踴躍成全 🙏」、報名連結；也可勾好幾筆「複製勾選的通知」合成一則。
2. **新增／編輯勤務**：名稱、性質、模式、日期型態、地點、時段、負責組、服裝、DM、說明、了愿項目與名額。
   - **職司表（2026/10/4，12人小組這類多天輪值）**：勤務可勾「用職司表顯示」（版面＝職司表；道務、教育與公告型不提供）。報名方式不變（選了愿項目→勾日期→填名字），家人們的勤務頁「報名名單」改成職司表：一欄一天（今天那欄標示）、第二列是每天人數（不含陪同）、一列一個了愿項目的格子（列數＝該項目人最多的那天，空格顯示「—」），左邊項目欄固定、表格左右滑；原本的每日名單收進「每天的名單（要取消或改期點這裡）」。**職司表大頁面** `#/grid/<勤務ID>`（可單獨分享）：行事曆點這種勤務一樣先到報名頁，報名頁有「📋 打開大張職司表」按鈕。上方藍色大標題（日期、名稱、地點時段）與階段進度條（膠囊，電腦一列、手機兩欄，現在的階段白底亮起），中間滿版職司表（第一次打開捲到今天那欄），下方職司說明與服裝（說明的版面：「【烹飪】」開頭的一行自成一區、左邊配圖示；**粗體**；「>」開頭的一行是小標重點，例：> 職司完整不空窗：前一天晚上 → 當天。報名頁的說明也一樣），浮動的「點我報名」到勤務頁並直接捲到報名表單；每 30 秒自動更新（保留左右滑的位置）。管理者在後台名單可「★ 設組長」（排在該格第一個，名字前顯示 ★）與「加註記」（最多 100 字，家人們點名字旁的「註」，在名字旁跳出小泡泡顯示姓名、日期與註記）；家人們報名時每個名字下也可以自己填「註記」（可空白，例：8:00-19:00、代理人），每筆報名各自設定，寫入操作紀錄。「階段」欄一行一個「日期｜說明」（例：即日起~9/13｜向區中心報名了愿日期），勤務頁上方顯示成時間軸：已過的變淡、今天所在的階段亮起並標「進行中」（今天不在任何階段時亮下一個）；日期年份跟著勤務開始日，跨年自動判斷。**「階段」留空時自動推算**（12人小組的節奏，三個階段）：③ 壇辦班職司最後調整＝輪值第一天之前的禮拜一（壇辦班都在禮拜一）；② 職司安排＝再前一週的禮拜一～禮拜五；① 報名了愿日期＝③ 往前三週的禮拜一～職司安排前一天（禮拜日）。例：11/8 開始 → 10/12~10/25、10/26~10/30、11/2(一)。後台表單會顯示推算結果；有填就用填的。
   - **合併顯示（2026/10/5）**：勤務可填「和同一天的項目合併顯示」（名稱含這幾個字，例：初一十五班填「拜香輪值」；可同名一起改）。行事曆（月曆格子、當天清單、週、近期）同一天有符合的項目時合成一張卡片：上面是先的那筆（🙏 名稱、時間、地點、輪值組），下面「接著　初一十五班」，徽章看要報名的那筆，點進去到要報名的那筆；報名頁最上面有「🙏 先：九月初一拜香輪值」區塊（時間、地點、輪值組、服裝，及「📖 接著：初一十五班（拜香完接著開始）」）。那天沒有符合的就單獨顯示。資料仍各自獨立（拜香算勤務、初一十五班看報名）。
   - **DM（2026/10/4）**：每筆可附最多 5 個照片或 PDF（照片自動縮成長邊 1600px 的 JPEG；PDF 最大 5MB），上傳後存在 Cloudflare（Durable Object SQLite 的 files 表，不同步到 Google 試算表；試算表「DM」欄只存清單 JSON：id、檔名、類型）。唯讀帳號不能上傳。家人們的勤務頁在資訊下方顯示「DM」：照片完整顯示、點了放大；PDF 是「📄 打開 PDF」大按鈕（另開分頁）。檔案網址 `API?action=file&id=F-…`，代號不重複使用，可長期快取。農曆規則可勾「初一」「十五」「閏月也要」並選產生年份。**多個日期（2026/10/4）**：新增時日期型態可選「多個日期」，一次建立同名的很多筆（例如一整年的時間表）：方法一「固定的日子」（從～到＋頻率：每週／每兩週／每三週／每四週＋勾星期幾，從「從」那一週算第 1 週；每月第一～第四個／最後一個＋勾星期幾；每月固定幾號，沒有那天的月份略過）、方法二「貼上日期清單」（認得 1/7、1月7日、2027/1/7、2027-01-07、民國 116/1/7，後面的（三）略過；只寫月日的用填的年份），兩種可一起用、重複只算一次，最多 200 個；按「產生並預覽」列出所有日期，可取消不要的（例如過年）再「確定建立 N 筆」。其他欄位填一次、每筆都一樣；不設報名截止日。教育的課程在預覽時每一天旁邊有「師資」欄（預設是表單上填的），可逐天改，或用「從～到＋師資＋套用到這段日期」一段一段指定。預覽時**國定假日紅字、預設不勾**並標節日名稱（元旦、除夕、春節初一～初三、和平紀念日、兒童節、清明節、勞動節、端午節、教師節、中秋節、國慶日、臺灣光復節、行憲紀念日；農曆節日用 lunar-javascript 換算，清明用節氣公式；不含行政院每年公告的調整放假）；**補假**（國定假日遇星期六→前一天補假、遇星期日→隔天補假）與**連假**（國定假日、補假、六日連在一起 3 天以上，連假裡的六日也算，標「中秋節連假」）一樣紅字、預設不勾，要的話可再勾回來。**重複提醒**：新增時同類別、同名、同一天已經有的才提醒（道務的闡道班課程和勤務的闡道班幫忙不算重複）。**同名一起刪**：刪除時若有同名的其他筆（seriesKey_），跳出清單可勾選一起刪（全選／只選今天以後的／都不選），有人報名的反灰不能勾；伺服器全部檢查過才刪，任一筆還有報名就整批不刪並列出是哪幾筆；每筆各寫一筆操作紀錄。
   - 農曆規則：選國曆起訖日期，負責組可「固定一組」或「依序輪流」，可勾「名稱前面加上農曆日期」（例「九月初一拜香輪值」）；送出前先列出所有日期確認。
   - 可「另存成新勤務」（以現有勤務為範本）。
   - **勤務已有人報名時**：有人報名的了愿項目不能刪除、有人報名的日期不能移出勤務期間、不能改成公告型（須先取消或改期）；「最多」可調低到比目前人數少，但會警告。
   - **刪除勤務**：只有沒有有效報名時才能刪除，連同了愿項目一起刪除。
   - **同名勤務一次改**：存檔時可勾選要一起套用的其他同名勤務與欄位（名稱、性質、模式、時段、地點、負責組、服裝、說明、了愿項目；日期不套用）。「同名」比對時去掉開頭的農曆日期與結尾的括號說明，所以「九月初一拜香輪值」與「十月十五拜香輪值（大典）」算同名。改名稱時只換掉改動的那一段（「九月初一拜香輪值」改「九月初一拜香開課」，其他筆變「十月初一拜香開課」）。其中一筆不能改就全部不存。
   - 新增、修改、刪除勤務都寫入操作紀錄（不提供還原）。
3. **批次匯入**：貼上多列（日期、名稱、地點、負責組…）一次建立多筆勤務。先檢查並預覽，有錯的列標紅，全部正確才能匯入。
4. **出席修正**：勤務結束後，預設「報名＝出席」；管理者可勾「未到」、補上沒報名但有來的人、改「陪同」。
   - 勤務當天（含）之前的名單才出現「改未到／改出席」「改陪同／改了愿」（只有壇辦能陪同）「補登」。補登不受日期限制，名額與同日重複只警告；每次修正寫入操作紀錄（動作「修正」）。未來的日期也可以由管理者「＋ 幫人報名」（同補登：直接記為有效報名、不受截止日與「當天不能報」限制，名額與重複只警告；操作紀錄寫「管理者幫人報名」；姓名欄打字時列出成員名單（啟用中、名字含所打的字，附身分），點了帶入姓名與身分；名單上已登記身分的以名單為準（伺服器也照這個規則）；職司表的勤務可同時填註記）。勤務管理的月份選單有「已過去（補登人員）」：列出已結束的勤務（最近的在前），點進去直接是報名名單（最後一天），選日期後按「＋ 補登」加人；已結束的勤務在其他篩選下點進去也是報名名單，名單頁有「編輯勤務 ›」。
5. **操作紀錄**：時間、動作、內容、還原按鈕。
6. **名單**（原「明日名單」，2026/10/5 改）：總管理者看全部類別，勤務／道務／教育帳號只看自己類別。列出今天起一個月有報名的日期（勾選、全選／都不選），產生文字複製貼 LINE，格式：第一行「教全區」，每個日期一段（單一天也寫日期，例「11/14（六）」），每個勤務一行「勤務名稱:名字、名字」（不分了愿項目、不含陪同重複，依報名順序）。
7. **成員名單管理**、**分組管理**。
   - 成員：依身分分類（壇辦／道親／未求道／未填身分，附人數，選「全部」時分段列出）、搜尋、新增、修改姓名／身分／三種分組／備註；「從出勤紀錄加入成員」列出報名紀錄裡有、名單還沒有的人（身分取紀錄裡最常出現的，和現有成員名字相近的預設不勾），勾選後一次加入；加入前可合併同一人的不同寫法（出勤紀錄裡彼此相近的選統一寫法，和現有成員相近的可併入該成員），報名紀錄的舊寫法一併改掉，同一場重複的改為已取消；剩下的怪名字可「清掉」：只是不再列出（統計照算），或連同出勤紀錄一起取消（統計不再算，紀錄標已取消不刪除）；先「停用」（停用後不出現在報名的名字提示），**已停用的才能刪除**（只移除名單，過去的出勤紀錄不受影響）。改名不影響過去的報名紀錄。
   - 分組：修改組長、佐理、組員、組長電話，可新增；**改組名時，勤務的負責組與成員的組別一併更新**；分組類型不能改（要換類型就新增一組）。還有勤務由該組負責時不能刪除；刪除時成員的該組別一併清空。
   - 這兩張表沒有 ID 欄，以列號找資料並核對原本的姓名（組名），避免同時有人在試算表調整時改錯列。

### 2026/10/5 優化：借場地備註、推播
- **借場地備註**：填資料多「備註」（選填，最多 100 字，例：要用投影機），只有後台看得到，和其他資料一起記在這台裝置。
- **查我的申請**：可勾選的上方有「全選／都不選」。
- **借場地推播**：總管理者、場管登入後台時，手機已經允許通知（例如開過手機提醒）就自動開啟場地申請通知（「場地借用」上方小字「✅ 這支手機會收到場地申請通知」＋「關閉」；自己關過的手機不再自動開；沒允許過通知的手機顯示「開啟場地申請通知」按鈕），有人送出申請或申請取消時收到「🏠 有新的場地申請」，點了打開審核頁。申請人送出後畫面問「要收到審核結果通知嗎？」，允許後同意／不同意／同意取消／不同意取消時那台手機收到結果（含原因）。只記推播網址與申請ID，不存姓名電話。

- **匯入歷史資料**：在管理後台選舊的統計 Excel（每月一個分頁，可一次選多個），瀏覽器讀取後各月與原檔「統計」分頁核對人數（以名單為準），列出疑似同一人（異體字、沒寫姓的簡稱）讓管理者選擇統一寫法；備註欄：「工作內容：名字」（如「視廳：○○」）算出勤人數，身分依同一批資料推斷、找不到記為未填身分；「○○陪同」「○○-護持」與其他單純名字歸陪同；「甲/乙/丙」代表多人；名字去掉「姐、哥、兄、師姐、師兄」等稱呼；看不懂的列出來給管理者看。每場建一筆已過去的勤務（說明註明歷史資料匯入），同名同日已存在就略過。預設不匯入本月起的資料（由新系統記錄）。

- **每週自動備份**（`Backup.gs`）：每週日凌晨 3 點把整份試算表複製到雲端硬碟「勤務行事曆備份」資料夾（檔名含日期），只留最近 12 份，更舊的移到垃圾桶；第一次由管理者在 Apps Script 執行 `setupBackup`（授權雲端硬碟、建立排程、立刻備份一次）。
